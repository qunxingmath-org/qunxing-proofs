# VER-010 · 证明复跑

PR 触及提交目录时，验证程序从 base 提交读取，只读取拟提交的 Git blob。检查允许的文件、2 MiB 限额、CON-020 Schema、记录清单、Git 对象、声明及锁定题面摘要。源文件扫描只记录需复跑的信号。只有受信锁定题面和工具链都对得上，才进入断网构建。

主分支每天从本仓库的提交计算队列。优先排开放题证明和否证，其余用合并 SHA 和路径确定性抽样，每天最多 30 项。每个作业最多 60 分钟，记录工件保存 90 天。作业没有仓库写权限或秘密，不写共享构建缓存。脚本分开生成 Challenge 与 Solution 构建目录，生成可信 TOML，忽略提交自带的构建产物。使用只读工具链、只读官方 Mathlib 和不联网的 bubblewrap。受保护配置要求 Lean、NanoDa 和 con-ron 比对，并另跑 `leanchecker --fresh`。

`ci/locks.json` 的每项 `challenges` 键为 `QX-P-…@card_rev`，内容包含权威 Challenge SHA-256、定理名和定义名。这些项只能从已审定的题卡加入。当前清单为空，未锁定和旧工具链回报待定。现有桌面样例用 Lean 4.25.0，本分支的独立内核配置锁定官方 4.35.0。请先统一批准的工具链，并添加一个权威题面以及成功与失败样例来验收真实复跑。

`verification.json` 是 CI 工件。后续由有窄权限的机器人从可信工作流按具体运行和提交取回，写回对应目录。比对通过才标记已复跑。反例或错误定理须写失败状态，缺依赖及超时保留待复跑。状态写回与熄灭待机器人到位后验收。
